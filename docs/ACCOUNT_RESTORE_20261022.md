# 업데이트·재설치 후 계정 기록 복원 점검

목적: 기존 진영이 있는 계정에 재선택 화면이 열린 원인을 수정하고, 업데이트와 앱 삭제 후 재설치를 구분해 데이터 복원 경로를 점검한다.

근거: `sessionScope.ts`, 각 persist 스토어, `useFactionSync`·`useProgressSync`·`useSettingsSync`·`useCollectionSync`·`useEngagementSync`, 실제 서버의 진영 고정 계약 및 격리 API 화면 검사. 작성자: Codex. 날짜: 2026-10-22.

## 원인과 변경

- 재설치로 기기의 `faction` 저장본이 없는 동안, 홈은 디스크 복원 완료만 확인하고 서버 진영 조회가 끝나기 전에 온보딩을 열었다.
- 선택 화면은 서버 저장 전에 로컬 선택과 성공 처리를 확정했다. 서버가 기존 진영 변경을 409로 거절해도 다른 진영이 기기에 남을 수 있었다.
- 서버 진영 확인이 성공한 경우에만 새 선택을 허용한다. 조회 실패·잘못된 응답은 미선택과 구분하며 재시도를 제공한다. 기존 서버 값이 있으면 그 값을 복원한다.
- 새 선택은 실제 서버 응답을 확인한 뒤 기기에 저장한다. 오프라인 큐 접수는 변경 불가 진영의 확정으로 취급하지 않는다. 동시 선택의 409는 서버 값을 재조회해 수렴한다.
- 진영 복원은 계정/세션 단위로 관리하고, 이전 세션의 늦은 응답은 적용하지 않는다. 서버에 아직 없는 유효한 기존 기기 선택은 서버 조회 후 이관한다.

## 데이터별 복원·마이그레이션

| 데이터 | 처리 |
|---|---|
| 진영 | 서버 고정값 우선. 잘못 남은 기기 값 정정. 서버 조회 실패 시 재선택 금지. |
| SRS·학습 이력·출석·일별 목표 | 디스크와 서버 복원을 기다리고 기존 병합 규칙 유지. 복원 데이터를 새 채점/출석으로 재전송하지 않는다. 기기 SRS가 비어 있으면 서버 복원 전 학습 화면의 채점 로직을 시작하지 않는다. |
| 계정 설정 | 디스크 복원 후 서버와 비교한다. 첫 조회가 진행 중일 때 초기값을 전송하지 않는다. `app-settings` v0/v1 → v2 마이그레이션을 추가해 프로필·경력·기기 취향을 정규화하며 보존한다. |
| 도감 | 서버 첫 조회 전에 빈 초기값을 동기화하지 않는다. 기존 단조 증가 카운터 병합과 v1~v4 잔액 이관은 유지한다. |
| 추천·저장 | 대기 쓰기를 먼저 전송한 뒤 복원한다. 서버 복원과 실제 사용자 토글을 구분하고 세션이 끝난 구독의 쓰기를 막는다. |
| 알림 | 목록은 서버에서 다시 읽는다. 구버전의 끄기/삭제 선택만 v4로 이관하며 데모 목록은 복원하지 않는다. 다른 계정으로 전환할 때 이전 계정의 끄기 선택은 넘기지 않는다. |
| 공유 글·질문·신고·기타 캐시 | 기존 서버 API와 로컬 backfill/계정 격리 경로 유지. 사용자 글과 예전 데모 글을 구분하는 기존 마이그레이션 유지. |
| 세션·테마·폰트·프로필 사진 등 기기 자료 | 덮어 설치는 앱 저장 공간을 유지한다. 삭제 후 재설치에서는 서버에 저장한 자료만 복원할 수 있다. 서버에 없었던 기기 전용 자료나 삭제 전 미전송 기록을 추정해 생성하지 않는다. |

과거 SRS v2 이전 데모 정리 규칙은 변경하지 않았다. 최초 자기 판단 등 서버 스냅샷에 없는 과거 값은 마지막 복습 결과로 추정하지 않는다. 별도 원본이 없는 자료의 복구를 보장하지 않는다.

홈에서 진영·학습/출석·설정·도감·추천/저장·알림의 복원 중/완료/실패를 계정별로 구분하고, 실패한 경우 초기화 없이 다시 불러올 수 있다. 알림 복원을 읽음 입력으로 재전송하지 않고, 신고와 공유 글 backfill도 디스크 복원과 세션 유효성을 확인한다. 운영 DB에 일괄 변경이나 데이터 재생성은 실행하지 않았다.

## 검증

- 수정 전 진영 회귀 검사에서 서버 조회 중/조회 실패 시 온보딩 노출 2건 실패를 확인했다.
- 진영 지연 복원, 잘못된 로컬 진영 정정, 409 고정 진영 복원, 저장 실패, 중복 탭, 세션 전환 및 구버전 설정/알림 이관을 검사한다.
- `scripts/qa/account-restore-check.mjs`는 빈 저장 공간의 재설치·조회 지연·조회 실패/재시도·선택 충돌에서 진영과 학습/출석/도감/설정/추천/저장 보존을 검사한다. 복원을 새 학습으로 전송하지 않는지 확인하고 앱바의 실제 이미지 바이트도 숫자 3 자산과 대조한다.
- 운영 확인은 지정 계정에 대한 회원 식별 조회와 PostgreSQL 읽기 전용 트랜잭션만 사용했다. 계정 식별 정보와 접속 정보는 이 문서에 기록하지 않는다.
