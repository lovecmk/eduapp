## 계약과 변경

- 운영 저장소 22종은 모두 실서버 API를 사용한다. 목업/샘플 자료 25개는 `src/__tests__/fixtures/`로 이동해 운영 코드에서 참조하지 않는다.
- 목업 환경변수 분기, 숨겨진 관리자·간편 데모 로그인, 가짜 운영 콘솔, 게시글·알림 초기 샘플, 로컬 보상 지급, 샘플 내보내기·생성 스크립트를 제거했다.
- API 미배포/404를 성공으로 감추지 않는다. 서버 확인 캐시와 계정별 쓰기 큐는 유지한다. 학습 완료 API가 거절하면 로컬 쿼터를 올리지 않는다.
- 모바일 작성 요청도 `format_nm`, `answer_txt`, `improvement_txt`, `note_txt`, `industry_nm`을 전달한다. 서버는 명시적 v2 필드와 기존 별칭을 받는다.
- `answer_txt`는 정답 원문, `conclusion_txt`는 해설 첫 문장의 구버전 별칭이다. OX 정답과 해설을 합치지 않는다. PostgreSQL 저장소의 format_nm 저장과 모바일 GET의 권고사항/참고사항 전송은 기존 구현을 재확인했다.
- WindowApp의 오래된 모바일 계약 점검표를 실제 v2 응답에 맞췄다.
- 모바일은 JWT, WindowApp은 Rust 쿠키 저장소의 브릿지 세션을 사용한다. 같은 브릿지 사용자·서버 권한을 보며 기존 인증 경계는 유지한다.

## 검증

모바일 타입 검사·Jest 전체·Expo 웹 번들과 격리 HTTP UI 검사, WindowApp 타입 검사·Vitest·Vite 빌드 및 스튜디오/배분/배포 브라우저 회귀 검사를 실행한다. 별도 린트 설정은 없다.

백엔드는 go vet·전체 단위/통합·레이스 검사와 실제 PostgreSQL 감사를 실행했다. 4,000개 카드, 300명 사용자, 40,200개 학습 기록, 동시/중복 요청, 만료·잘못된 토큰, 권한 거부, 긴 입력·이모지, DB 차단·연결 종료, 0/1/대량 경계, 검수·전송·배포·취소·재배포를 확인했다. 스키마와 당시 보정 절차를 검사했다. 아래 2026-10-15 보정 정책이 현재 기준이며, 구형 분류 덮어쓰기 SQL은 재실행하지 않는다.

## 데이터 정리

백업 후 명시적 `qa_release_*` 과거 시험 사용자 300명과 연결 기록을 삭제했다. 이번 감사의 생성 카드·초안·프로젝트·사용자는 종료 시 트랜잭션으로 정리한다. 마이그레이션이 복제한 QA 초안 4,001건과 전송 기록도 별도 백업 후 제거했다. 보완한 코드로 실제 DB 극한 시험을 재실행하여 QA 카드/초안/프로젝트/사용자 0건, 실제 카드 25건/초안 135건/프로젝트 9건의 보존을 확인했다. 이용재님의 94장 프로젝트와 기존 프로젝트를 보존했다. 시험 여부가 불명확한 기존 `test1/2/3` 프로젝트는 이름만 보고 임의 삭제하지 않았다.

94장 프로젝트가 서비스 카드 통계에 나타나지 않는 이유는 계정이 아니라 아직 운영 카드로 배포되지 않았기 때문이다. 검수 완료, MY 카드 보내기 전송, 관리자 앱 배포는 별도 단계다. 실제 사용자 카드를 임의 전송·배포하지 않았다.

## 릴리스와 서버 담당자의 작업

모바일은 `vX.Y.Z-<short SHA>`, WindowApp은 `vX.Y.Z` 태그로 main과 함께 발행한다. 모바일의 APK/Web/OTA 태그 빌드는 모두 커밋된 버전을 검증하며 patch/빌드 번호를 다시 올리지 않는다. 초기 OTA의 이중 증가 설정도 바로잡고 후속 patch 태그로 세 산출물 버전을 일치시켰다.

웹 번들 gh-pages 게시와 실제 호스팅을 구분한다. GitHub Pages 활성화 API는 현재 비공개 저장소 요금제가 지원하지 않아 422를 반환했다. 공개 전환/요금제 변경은 하지 않았으며, 워크플로우는 호스팅 미설정 상태를 경고한다. 서버 담당자는 지원 요금제 또는 별도 웹 호스트를 준비해야 웹 주소가 열린다.

백엔드는 **dev 커밋만 하며 push·서버 배포는 하지 않는다.** 서버 담당자는 새 백엔드를 기존 브릿지 절차로 먼저 배포한 뒤 health·브릿지 로그인·v2 저장/조회·사진 버전·배분/명시적 전송을 확인해야 한다. 구형 `20261014_studio_taxonomy.sql` 분류 덮어쓰기는 폐기되었다. 스키마/배포취소 호환 절차와 새 `d3m-repair-taxonomy` 범위 보정을 사용한다.

로컬 Cargo는 crates.io 설정 요청이 JSON 대신 HTML로 돌아와 패키징이 막혔다. 태그 Actions에서 네이티브 패키징을 확인한다. 실기기 푸시 수신/OS 백그라운드 동작과 실제 사용자 계정 로그인은 기기·계정의 최종 확인이 필요하다. QA 계정·API 통합과 권한 경계는 자동 검증했다.

## 재점검 (2026-10-15)

목적: 신규 3개 프로젝트 동기화 요청의 최신 검증 기록. 기준: Go DTO/domain과 App CardMapper, WindowApp 동기화 기록. 작성자: Codex. 작성일: 2026-10-15.

category_cd는 기존 네 집계 영역의 호환 코드를 유지하고 taxonomy_category_cd/nm은 실제 기술 분류를 보존한다. 카드 경로는 전기/배전·제어설비처럼 표시하고 기존 필터/개인화 집계는 유지한다. 알 수 없는 코드의 전기 위험 폴백을 현장 점검으로 수정했고, 구형 응답에 해설 별칭이 없으면 OX 이외의 정답 원문을 사용한다. O/X 자체를 해설로 표시하지 않는다.

기존 홈 학습 완료 카드 수, 상황/질문 동일 글꼴, 뒷면 섹션 순서·빈 항목 숨김, 뒷면 좋아요/저장/신고, 복습의 최초 선택·이번 선택 분리를 재검증했다. total_learned는 현재 조회 가능한 MASTERED 카드 ID의 중복 없는 수이며 평생 누적 학습 횟수가 아니다.

타입 검사와 Jest 121개 suite/984개 test, Expo 웹·Android·iOS 번들, 카드 표시 19개/학습 5개/전체 화면 16개 UI 검사를 통과했다. Expo SDK 52와 의존성은 유지했다. QA 정적 서버는 export 폴더 이름에 점이 있어도 디렉터리를 파일로 읽지 않도록 수정했다.

실DB 초안 137건의 프로젝트 분류 오염은 백업 후 75건 복원/62건 불확실 분류 비움으로 보정했다. 실DB E2E/대량·동시·권한·신고·재검수·삭제 검증과 생성 시험 자료 정리를 완료한다. 실제 OpenAI 5장 생성도 확인했다. 전체 DB 시험과 UI의 격리 API 회귀는 구분한다. 백엔드 dev 변경은 push/배포하지 않으며 서버 담당자 반영이 필요하다. 새로운 기술 분류 필드가 없는 기존 서버에는 기존 분야 표시로 호환한다.
