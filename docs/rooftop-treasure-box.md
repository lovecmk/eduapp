# 커뮤니티 진영 비교와 옥상 보물상자

목적: 기존 빌딩·도감 보상을 서버 판정으로 연결하고 앱/API 계약과 운영 절차를 고정한다.
작성: Codex, 2026-10-06. 근거: `buildingCrates.ts`, `CommunityBuildCard.tsx`, 도감 Repository 및 KFPA BE `daily3min` 구현.

## 조사 결과와 결정

기존 앱은 세 진영 비교·상자 연출·팩/조각 지급을 구현했지만 상세는 접힌 상태였다. 실제 서버는 `building.current.factions`와 `/me/faction`을 구현하지 않았고, 우승 진영을 고정 비율로 추정했다. 보물상자 전용 라우트·테이블·서버 추첨은 없었다. `claimedRules`의 클라이언트 병합만으로는 여러 기기의 동시 개봉이나 위조를 막을 수 없었다.

이제 진영별 월간 서버 학습 이력을 집계해 순위, 층수, 문제 수, 비중, 다음 층 진행도를 모두 펼쳐 표시한다. 내 진영은 색과 `(나)`로 강조한다. 세 진영 모두 0이어도 세 행을 반환하고, 집계 API가 없는 구버전은 집계 준비 상태를 표시한다. 진영 집계에는 사용자 ID·이름·개인 기여 내역이 없다. 동일 기여는 동률이며 우승자를 임의로 만들지 않는다. 최초 선택은 서버에 저장하고 이후 변경은 금지한다.

진영 데이터를 아직 받지 못한 경우에도 빌딩 영역을 숨기지 않고 로딩·빈 상태·API 오류와 재시도 버튼을 표시한다.

## 획득 조건·경제

빌딩은 전체 커뮤니티가 함께 쌓는 월간 빌딩이다. 진영 비교는 별도 집계이며 상자 조건은 모든 진영에 동일하다. 서버에 수락된 `learn_history`의 카드/사용자/KST 날짜 조합 한 건을 벽돌 한 장으로 센다. 같은 카드의 같은 날 재전송은 기본키로 중복을 막는다. 클라이언트 월간 카운터·층수·보상액은 실제 모드에서 인정하지 않는다. 질문/좋아요 도배로 열쇠를 주지 않는다. 별도 소모형 열쇠 대신 **공동 층수 + 개인 학습 기여**를 획득 조건으로 사용한다.

| 층 / 등급 | 개인 월간 벽돌 | 보상 / 확률 |
|---|---:|---|
| 5 / 기초 — 벽돌 꾸러미 | 1 | 팩 1개 100% |
| 10 / 안전모 | 5 | 팩 1개 + 조각 30, 100% |
| 20 / 깜짝 자재 | 10 | 팩 1/2/3개 각각 60%/30%/10% |
| 35 / 황금 | 20 | 팩 2개 + 조각 60, 100% |
| 50 / 옥상 파티 | 30 | 팩 3개 + 조각 100, 100% |

한 층은 20,000개의 서버 학습 이력이다. 상자는 사용자별 매월 각 층 한 번(최대 5개), KST 하루 최대 3개, ISO 월요일 주간 최대 5개, 서로 다른 상자 사이 60초 쿨타임이다. 월이 바뀌면 미개봉 상자는 만료한다. 이미 처리된 요청은 월이 바뀌거나 한도를 채워도 원래 결과를 반환하고 추가 지급하지 않는다.

팩은 기존 도감 보관함에 적립하고 조각은 기존 교환 잔액에 합산한다. 같은 수집 카드의 중복은 기존 팩 개봉 규칙에 따라 조각으로 처리한다. 추가 XP·랭크 점수·엠블럼을 따로 지급하지 않는다. 학습 자체의 기존 XP·랭크·업적과 중복 적립을 막는 결정이다. 이 작업은 **옥상 상자의 서버 지급**을 보장한다. 기존 일반 팩의 오프라인 추첨과 일반 도감 카운터는 기존 클라이언트 병합 모델이며 이를 전면 서버 경제로 바꾸는 작업은 범위 밖이다.

## UI 흐름과 실패 처리

커뮤니티 → 모든 진영 현황 → 옥상 상자 선택 → 조건/보상 확인 → 흔들리는 개봉 연출 → 서버 응답 후 보상 표시 → 카드팩 열러 가기/도감 보관함. 실제 서버 개봉 내역은 아래에 월·층·팩·조각으로 표시한다. 요청 중 중복 탭을 차단한다. 연결 오류·미배포(404/503)는 재확인 버튼을 표시하고 지급하지 않는다. 개봉 응답 또는 후속 잔액 조회가 끊기면 같은 월/층으로 재시도해 원래 결과를 복구한다. 계정 전환 후 늦게 도착한 응답은 새 계정 도감에 적용하지 않는다. 학습 기여는 15초마다 새로 조회한다.

`EXPO_PUBLIC_USE_MOCK_DATA=true`는 기존 시연 도감에만 지급한다. mock Repository와 스토어도 월별 횟수·하루/주간 한도·쿨타임을 검사한다. 실제 모드는 mock으로 자동 폴백하지 않으며 로컬 `openBuildingCrate`도 지급을 거부한다.

## API 계약

모든 라우트는 인증 및 활성 계정 검증 뒤에 등록한다. 사용자 식별은 JWT에서만 얻는다.

| API | 요청 | 응답 |
|---|---|---|
| `GET /inner/api/v1/me/faction` | 없음 | `{ faction_cd: "frost"/"flame"/"volt"/"" }` |
| `POST /inner/api/v1/me/faction` | `{ faction_cd }` | 동일 진영; 변경 시 409 |
| `GET /inner/api/v1/community/live` | 없음 | `building.current/history[].factions: [{ faction_cd, problems }]` |
| `GET /inner/api/v1/community/rooftop` | 없음 | `{ month, floors, my_bricks, history: [receipt] }` |
| `POST /inner/api/v1/community/rooftop/open` | `{ month: "YYYY-MM", floor: 5/10/20/35/50 }` | `receipt` |

receipt는 `{ month, floor, packs, shards, opened_at: RFC3339 }`이다. 보상 원장의 본인 내역만 최근 60건 반환한다. 잘못된 요청 400, 인증 401, 조건 불충족/월 만료 409, 한도/쿨타임 429, 지원하지 않는 저장소 503. 앱은 응답 enum·범위·시각·요청 월/층 일치까지 검사한다.

도감 응답에 `rooftop_packs`, `rooftop_shards`를 추가한다. 기존 일반 적립 카운터와 독립된 서버 누계로, 앱은 잔액 계산에만 합산한다. 동기화 요청에 보내지 않고 서버도 입력을 읽지 않는다. 구버전 앱은 새 필드를 무시한다. `bld:` 규칙의 클라이언트 위조도 거부한다.

## 서버 트랜잭션·운영

`community_factions`는 진영 선택을 저장한다. `rooftop_claims`는 지급·재고·감사 원장이고 PK `(user_id, month, floor)`로 월별 중복을 금지한다. PostgreSQL advisory transaction lock으로 같은 사용자의 모든 상자 요청을 직렬화한다. 잠금 안에서 기존 개봉 조회 → 조건·한도 검증 → 암호학적 난수 추첨 결과 저장 → commit한다. 원장 합계 자체가 잔액이므로 지급만 되고 기록이 없는 부분 성공은 없다. 쿼리는 매개변수 바인딩으로 실행한다.

BE `daily3min/postgres/migrations/20261006_rooftop.up.sql`은 반복 적용 가능하다. 신규 테이블만 만들고 기존 회원·학습 데이터는 수정하지 않는다. `schema.sql`/임베드 상수도 동기화해 정상 부팅에 누락되지 않게 한다. PostgreSQL 운영 배포가 필요하며 Mongo/memory 서버는 명시적으로 503을 반환한다.

롤백 전 진영·원장을 반드시 백업한다. 아직 지급을 사용하지 않은 검증 단계는 down SQL로 되돌릴 수 있다. 지급/소비 후에는 down으로 보상 원장을 지우지 말고 앱/서버 기능을 비활성화한 뒤 백업 원장을 유지한 상태에서 복구한다. 모바일에 서버 적립이 이미 동기화됐다면 단순 테이블 삭제로 경제를 되돌릴 수 없다.

## 재검증

- 모바일: `npm run typecheck`, `npm test -- --runInBand`, `npx expo export --platform web --output-dir dist-audit`.
- BE: `go test ./daily3min/...`, `go vet ./daily3min/...`, `go build ./daily3min/bridge ./daily3min/cmd/d3m-dev`.
- 실제 PostgreSQL/TCP: `PERSONALIZATION_POSTGRES_TEST=1 go test ./daily3min/postgres -run Rooftop -v`. 기본값은 로컬 테스트 PG 55437이며 별도 허가한 DB는 `PERSONALIZATION_TEST_DATABASE_URL`로 전달한다. 새 무작위 `test_e2e_rooftop_*` 스키마만 생성·삭제하므로 다른 서비스 데이터에 쓰지 않는다.
- 확률 경계/60:30:10, KST 월 경계, 일일·주간 한도, 쿨타임, 40개 동시 개봉, 실제 HTTP 인증/입력/IDOR, 위조 동기화, 반복 마이그레이션·롤백을 자동화한다.
