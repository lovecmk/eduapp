# 서버·콘솔 인수인계 — 이 저장소에서 볼 수 없는 쪽

서버(`backend/`)와 관리 콘솔(`admin/`)은 이 저장소를 떠나 **다른 사설 저장소**
(KFPA 브릿지)로 들어갔다. 이 저장소에서 일하는 사람은 그쪽 코드를 열 수 없다.
그래서 "저쪽 README 를 봐라"가 통하지 않는다 — **앱을 고치는 데 필요한 서버·콘솔
지식을 여기에 옮겨 적는다.**

> 이 문서는 **2026-08-13 기준 사본**이다. 저쪽이 바뀌어도 여기가 자동으로 따라오지
> 않는다. 의심스러우면 실제 서버에 물어 확인한다 — `GET /api/health`(버전),
> `GET /api/config`(지금 운영값). 엔드포인트 명세 자체는
> [API_CONTRACT.md](./API_CONTRACT.md) 가 정본이고 그것은 이 저장소에 있다.

## 1. 지형

| | 어디 | 이 저장소에서 |
|---|---|---|
| 모바일 앱 | **이 저장소** | 전부 고칠 수 있다 |
| Go 서버 | 브릿지 저장소 `BE/daily3min/` | 볼 수 없다. 변경은 요청해야 한다 |
| 관리 콘솔(Vue) | 같은 저장소 `FE/mybrdg/.../Daily3Min/` — 브릿지 운영관리 안의 한 페이지 | 볼 수 없다 |
| 회원·등급 | 브릿지 회원 테이블(`cyber_user`) | 서버가 **읽기만** 한다 |

서버는 **브릿지 웹 서버 프로세스 안에 얹혀** 돈다. 별도 프로세스가 아니다.
API 주소는 분리 전과 같다(`/api/auth/...`, `/api/progress`, `/api/admin/...`) —
이미 배포된 앱이 그 주소를 알고 있어 바꾸지 않았다.

## 2. 서버가 어떤 조건에서 도는가 (앱에 영향 있는 것만)

| 사실 | 앱에서 무엇을 뜻하나 |
|---|---|
| 프록시가 `/api/*` 를 브릿지 프로세스로 넘겨야 붙는다 | 새 환경에서 안 붙으면 **먼저 `GET /api/health` 가 인증 없이 200 인지** 본다. 여기서 막히면 앱 코드 문제가 아니다 |
| `D3M_ENABLED=false` 로 서버만 통째로 끌 수 있다 | 브릿지 웹은 멀쩡한데 앱만 전부 실패하는 상태가 **정상 운영 절차**로 존재한다 |
| 속도 제한 기본 **분당 240회/호출자** (`/api/health` 제외) | 오프라인 큐가 복구 순간 한꺼번에 몰리면 **429**. 재전송은 몰아치지 말고 간격을 둬야 한다 |
| 호출자는 `X-Forwarded-For` 맨 앞으로 센다 | 프록시가 그 헤더를 안 채우면 **전 사용자가 버킷 하나를 공유**한다 — 남의 폭주로 내 로그인이 429 가 된다 |
| 액세스 토큰 15분 · 리프레시 30일(기본값) | 15분마다 refresh 가 돈다. 리프레시가 죽으면 30일 안에 전원이 로그아웃된다 |
| 배선 실패는 "그 기능 미등록 + 로그" 로 끝난다 | 서버가 반쯤 뜬 상태가 가능하다 — **일부 경로만 404** 인 상황이 정상적으로 존재한다(§6 폴백) |

## 3. 회원 — 앱이 만들 수도 고칠 수도 없다

로그인은 브릿지 계정으로 한다. 서버는 회원을 **읽기만** 하고 비밀번호를 저장하지
않는다.

| 브릿지 | 하루3분에서 |
|---|---|
| `_id` | 사용자 id — 학습 데이터의 `user_id` 가 이 값이다 |
| `user_id` **또는** `email` | 로그인 아이디 — **둘 다 받는다**(사람들이 외우는 건 대개 이메일) |
| `password`(bcrypt) | 그대로 검증 |
| `admin == true` 또는 `level == "1"` | 관리자(콘솔 접근) |
| `new_level`(없으면 `level`) | 등급 — 브릿지 코드를 **그대로** 싣는다 |
| `able == false` | 사용 불가 — 로그인 차단 |

등급 코드: `admin · S · K · M1 · M2 · O1 · O2 · G1 · G2 · G3 · G4`
(어드민 · 슈퍼어드민 · 협회직원 · 사원사 · 사원사(대리점) · 비사원사(연간) ·
비사원사(연간 미가입) · 일반회원 4종). 모르는 코드가 와도 서버는 거르지 않고
그대로 싣는다 — **앱도 모르는 등급 코드에서 죽지 않아야 한다.**

그래서 앱에 **회원가입·비밀번호 찾기·프로필의 계정 정보 수정이 없다**(목업
모드에서만 보인다). 관리 콘솔에서조차 권한·상태 변경은 막혀 있고 누르면 409 와
"브릿지 회원관리에서 변경하세요" 가 뜬다.

## 4. 서버에 실제로 등록된 경로

[API_CONTRACT.md](./API_CONTRACT.md) 가 상세 명세다. 여기서는 **실제 등록 여부와
성격**만 옮긴다(계약서에 있는데 서버에 없으면 앱은 404 → 목업 폴백으로 샌다).

### 인증 없이

| 경로 | |
|---|---|
| `GET /api/health`, `GET /api/daily3min/health` | 속도 제한·점검 모드 모두 통과 |
| `GET /api/config` | 운영값 공개 (§5) |

### 로그인

`POST /api/auth/login` · `refresh` · `logout` · `register`(가입 개방 시에만) ·
`GET /api/auth/username-available` · `nickname-available` ·
`GET/PATCH /api/auth/me`

### 학습·콘텐츠 (토큰 필요)

`GET /api/cards` · `PATCH /api/cards/:id` · `GET /api/stats` ·
`GET /api/community/live` · `GET /api/cards/images/:id` ·
`POST /api/push/register` · `POST /api/telegram/alert`

> `POST /api/cards`(문제 등록)는 **관리자만** 통과한다. 앱 안에 문제 등록 화면이
> 있던 시절의 잔재이고, 지금은 토큰만으로 부를 수 없다.

### 동기화 (토큰 필요, 쓰기는 전부 멱등)

`GET /api/progress` · `POST /api/progress/grade` · `POST /api/progress/attendance` ·
`GET /api/engagement` · `POST /api/engagement/like` · `bookmark` ·
`POST /api/reports` · `GET /api/reports/mine` ·
`GET /api/notifications` · `POST /api/notifications/read-all` · `POST /api/notifications/:id/read` ·
`GET /api/collection` · `POST /api/collection/sync`

### 하루 학습 (토큰 필요)

`GET /api/learning/today` · `GET /api/learning/quota` ·
`POST /api/learning/complete`(멱등) · `GET /api/cards/today`(구형, 같은 편성을 구형 형식으로)

> **멱등키가 진짜로 동작한다.** 위 쓰기 경로는 `Idempotency-Key` 헤더를 서버가
> 읽는다. 분리 전에는 앱이 헤더를 보내는데 서버가 무시해서, 오프라인 큐가
> 재전송하면 출석이 두 번 찍히고 신고가 중복 접수됐다. 큐 재전송 시 **같은 키를
> 유지**해야 그 보호가 산다.

### 사진 주소는 하나뿐이다

앱이 쓰는 것은 `GET /api/cards/images/:id`(앱 Bearer 토큰)뿐이다. 발행된 문제의
`image_url` 에도 이 주소가 실린다. 콘솔용 주소(`/api/admin/studio/images/:id`)는
브릿지 세션 쿠키를 요구하므로 **앱에서 부르면 401** 이다.

## 5. 운영자가 재배포 없이 바꾸는 값 — `GET /api/config`

콘솔의 **운영 설정** 화면이 이 값을 즉시 바꾼다. 앱은 이것을 **권위로 받아야
하고 오래 캐시하면 안 된다.**

| 필드 | 뜻 |
|---|---|
| `maintenance_yn` / `maintenance_msg` | 점검 모드. 켜지면 일반 사용자 API 가 **503** (관리자는 통과) |
| `signup_enabled` | 꺼지면 신규 가입만 막힌다(기존 사용자는 그대로) |
| `daily_min_cards` / `daily_max_cards` | 하루 출제 **범위**. 정확한 장수는 그날 그 사람의 난이도가 정한다 |
| `daily_new_limit` | 하위호환 필드 — 값은 `daily_max_cards` 와 같다 |
| `notice_txt` / `notice_level` | 비어 있지 않으면 앱 상단 배너 |
| `version` | 서버 버전 |

> ⚠️ **점검 모드와 앱 폴백이 부딪힌다.** 점검 모드의 응답은 503 인데, 앱의
> `_fallback.ts` 는 503 을 '일시 장애(TRANSIENT)'로 분류해 보조 기능(하루 쿼터·
> 날씨·사용자 디렉터리)을 60초 동안 목업으로 떨어뜨린다. 즉 **점검 중인데 하루
> 상한만 로컬 값으로 도는** 상태가 만들어진다. 핵심 기능(auth·card·stats·
> community)은 폴백하지 않으므로 정직하게 실패한다. 점검 모드를 제대로 다루려면
> `/api/config` 의 `maintenance_yn` 을 먼저 보고 화면을 덮는 쪽이 맞다 — 지금
> 코드가 그렇게 되어 있는지는 확인이 필요하다.

## 6. 관리 콘솔이 하는 일 — 앱에서 보이는 결과

콘솔은 브릿지 운영관리 안의 한 페이지다. 화면은 열넷이고, 앱에 영향을 주는
것만 추리면 이렇다.

| 콘솔 화면 | 무엇을 하나 | 앱에서 보이는 것 |
|---|---|---|
| 대시보드 · 서비스 상태 · 분석 | 읽기 전용(현황·지연·학습 진단) | 없음 |
| 사용자 목록/상세 | 조회. **권한·상태 변경은 막혀 있다**(409) | 없음 — 계정은 브릿지가 쥔다 |
| 문제 관리(목록·편집기) | 문제를 손으로 쓰고 고친다 | 발행된 문제가 곧 앱의 학습 카드 |
| 생성·검수 스튜디오 | 프로젝트 → 원본(PDF·사진) → AI 생성 → 배정 → 검수 → 발행 | 통과한 것만 발행된다 |
| 신고 처리 | 앱에서 올라온 `POST /api/reports` 를 단계별로 처리 | `GET /api/reports/mine` 의 상태가 바뀐다 |
| 공지 센터 | 등급을 대상으로 공지 발송(대상 규모 미리보기 후) | 앱 알림 목록에 꽂힌다 |
| 운영 설정 | §5 의 값들 | 즉시 반영돼야 한다 |
| 관리 이력 | 변경만 기록(조회는 안 남긴다) | 없음 |

**발행 규칙 하나는 앱 데이터에 직접 걸린다.** 이미 발행된 문제를 고칠 때
발행 취소를 하지 않는다 — 취소는 운영 문제와 그 **학습 기록까지** 지운다. 대신
검수를 다시 통과시켜 재발행하면 같은 카드가 **갱신**되고 학습자의 진행 기록은
남는다. 그래서 앱은 "카드 내용이 조용히 바뀔 수 있다"를 전제로 해야 한다
(카드 id 는 그대로, 내용만 바뀐다).

## 7. 두 저장소에 걸친 짝 — 한쪽만 고치면 어긋난다

저쪽을 볼 수 없으므로, **여기 옮겨 적은 내용이 대조 기준**이다.

### 7.1 하루 출제 범위 (숫자)

| 이 저장소 | 서버 |
|---|---|
| `src/constants/learning.ts` — `DAILY_MIN_CARDS = 3`, `DAILY_MAX_CARDS = 5` | 기본값 min 3 / max 5 (운영 설정으로 덮인다) |

어긋나면 **서버에 닿은 기기와 못 닿은 기기가 다른 분량**으로 돈다 — 같은 사람이
태블릿에서 3장, 휴대폰에서 5장을 받는다.

### 7.2 오늘의 출제 규칙 (알고리즘)

| 이 저장소 | 서버 |
|---|---|
| `src/domain/dailyPlan.ts` (오프라인용) | `service/daily_plan.go` (평상시 권위) |

두 벌인 이유는 오프라인이다 — 지하·철골에서 서버에 못 닿는 날 "오늘의 학습이
없습니다"를 띄우면 그날 학습이 없던 일이 된다. **서버 쪽 규칙은 이렇다:**

1. 그 사람의 학습 신호로 오늘의 난이도를 정한다(쉬움/보통/어려움).
   운영 설정에서 적응형 난이도를 끄면 **늘 쉬움**으로 낸다.
2. 난이도가 장수를 정한다 — 쉬움이 많이(max 쪽), 어려움이 적게(min 쪽),
   보통은 그 사이. min/max 는 §5 의 운영값이다.
3. **복습 도래 카드를 먼저** 채운다(많이 밀린 순, 동률이면 카드 id 순).
4. 남는 자리는 `(사용자 id, 날짜)` 를 시드로 섞은 뒤 난이도가 가까운 순으로 채운다.
   무작위를 쓰면 앱을 다시 열 때마다 문제가 바뀌어 학습이 아니라 뽑기가 된다.
5. 그날 편성은 **처음 물어본 순간 저장돼 얼려진다.** 관리자가 낮에 문제를
   추가·삭제해도 오전에 받은 목록이 오후에 달라지지 않는다.

규칙을 바꿔야 하면 **서버 쪽 변경을 함께 요청해야 한다.** 앱만 고치면 온라인과
오프라인에서 같은 사람이 같은 날 다른 문제를 본다.

### 7.3 폴백 판단 ↔ 라우트의 존재

`src/data/repositories/_fallback.ts` 는 404·501 을 '미배포'로 보고 **앱 세션 내내**
그 기능을 목업으로 돌린다(화면에는 아무 오류도 안 뜬다). 서버가 반쯤 뜬 상태가
정상적으로 존재하므로(§2), 저쪽에서 경로를 지우거나 이름을 바꾸면 **앱은 조용히
가짜 값을 보여 준다.** 서버 변경 통보를 받으면 §4 목록과 대조한다.

## 8. 이 저장소에서 확인하는 법

| 모드 | `EXPO_PUBLIC_API_BASE_URL` | 확인되는 것 |
|---|---|---|
| 목업 | (빈 값) | 화면·상태·오프라인 규칙 |
| 테스트 | `http://test.inplat.org:8090` (사내망) | 실제 서버 — 계정·등급·권한·운영값 전부 |
| 운영 | `https://bridge.kfpa.or.kr` | 실사용 |

주소가 `http://` 면 `app.config.js` 가 그 호스트에만 평문 예외를 붙인다(README
"어느 서버를 보는가"). 지금 무엇을 보고 있는지는 `개발자 모드 > 환경 설정` 과
빌드 로그 첫 줄(`[app.config] API=...`)에 나온다.

> 서버 저장소에 접근할 수 있는 사람에게는 DB·로그인 없이 도는 메모리 개발 서버가
> 하나 더 있다(`go run ./daily3min/cmd/d3m-dev` → `:8091`, 카드·회원 시드 포함).
> 다만 **모든 요청을 관리자로 처리**하므로 권한 분기 확인에는 쓸 수 없고, 기본
> 바인딩이 `127.0.0.1` 이라 실기기에서 붙으려면 주소를 열어야 한다.

## 9. 앱 쪽에 남은 뒷정리

분리하면서 앱 안에 **갈 곳을 잃은 화면과 죽은 참조**가 남았다. 지울지 개발자
모드로 옮길지는 결정이 필요하므로 적어만 둔다.

### 9.1 앱 안의 관리 콘솔 — `app/admin.tsx`

콘솔은 브릿지로 갔는데 앱 안에도 같은 이름의 화면이 남아 있다. 이 화면이 읽는
것은 전부 **로컬 목업**이다(`mockUserDb`, `PACK_RULES`, `COLLECTIBLES`,
`settingsStore`, `authoredCardsStore`). 실서버 모드에서 열어도 운영과 아무 상관
없는 숫자가 나온다. 게다가 들어가는 길이 **모두에게 열려 있다.**

| 자리 | 내용 |
|---|---|
