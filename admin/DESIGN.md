# 관리 콘솔 디자인 시스템

이 문서는 **규칙**을 적는다. 색값과 컴포넌트 코드는
[`src/styles/base.css`](src/styles/base.css) 와 `src/components/` 에 있고, 그쪽이
언제나 정본이다. 여기서는 "왜 그렇게 정했는가"와 "새 화면을 만들 때 무엇을
따라야 하는가"를 다룬다.

전제 하나: **이 도구는 운영자가 하루 종일 띄워 두는 화면이다.** 그래서 예쁜
것보다 오래 봐도 피로하지 않고, 한 화면에 정보가 많이 들어가고, 상태 변화가
눈에 띄는 것을 우선한다.

---

## 1. 정보 구조와 화면 레이아웃

### 1.1 네 개의 면

```
┌──────────┬──────────────────────────────────────────────────────────┐
│          │  상단 바 (AppHeader)                          sticky      │
│  사이드바 │  ⌘K 검색·이동    …    [저장소 경고] 실시간● 🔔3 │ 테마 계정 │
│          ├──────────────────────────────────────────────────────────┤
│  대시보드 │  page-head                                                │
│  분석     │  제목 / 한 줄 설명                        [화면별 동작]   │
│  사용자   │ ─────────────────────────────────────────────────────────│
│  문제 관리│                                          ┌───────────────┐│
│  신고 관리│  본문 (Main Stage)                       │ 서랍          ││
│  서비스   │  · 지표 타일 띠                          │ (AppDrawer)   ││
│  관리 이력│  · 표 · 그래프 · 판(panel)               │ 오른쪽에서     ││
│          │                                          │ 밀려 나온다    ││
│  sticky   │                                          └───────────────┘│
└──────────┴──────────────────────────────────────────────────────────┘
                                                    ┌──────────────┐
                            파괴적 동작만:            │ 모달 AppDialog│
                                                    └──────────────┘
```

### 1.2 각 면이 지는 책임

| 면 | 무엇을 담나 | 판단 기준 |
|---|---|---|
| **사이드바** | 이동만 | 도메인 간 이동 외에는 아무것도 두지 않는다 |
| **상단 바** | 화면과 무관하게 항상 참인 것 | 연결 상태, 신고 건수, 저장소 장애, ⌘K, 테마, 계정 |
| **본문** | 그 화면의 데이터와 동작 | 제목·설명·화면별 버튼은 `page-head` 가 맡는다 |
| **서랍** | 맥락을 지키며 보는 상세 | 목록을 뒤에 남겨야 하는가? → 예 |
| **모달** | 되돌릴 수 없는 동작의 확인 | 맥락을 끊어야 하는가? → 예 |

**사이드바를 이동 전용으로 비운 이유.** 검색·테마·계정이 메뉴와 한 기둥에
섞여 있으면, 메뉴를 찾을 때마다 관련 없는 것들을 눈으로 걸러 내야 한다.

**상단 바에 무엇을 올릴지 고르는 기준은 하나다 — 화면과 무관하게 항상 참인가.**
실시간 연결이 끊기면 화면의 모든 숫자가 옛것이 된다. 그 사실은 대시보드에
있을 때만 참인 게 아니다. 신고와 저장소 장애도 마찬가지다. 반대로 화면 제목이나
그 화면의 동작을 상단 바에 올리면, 상단 바가 화면마다 달라지고 — 그 순간
상단 바를 보는 습관 자체가 무너진다.

### 1.3 목록 화면의 표준 형태

```
page-head          제목 · 설명                    [CSV] [새로 만들기]
─────────────────────────────────────────────────────────────────
chips              [전체] [정지된 계정] [관리자] [삭제된 계정]   ← 자주 쓰는 조건
─────────────────────────────────────────────────────────────────
panel
  panel-head       [🔍 검색  /] [권한 ▾] [상태 ▾] [초기화]   … 2명
  table            sticky th · 정렬 가능 · 줄 hover → 빠른 동작
  pager            1–30 / 128                        [이전] [다음]
```

조건(검색·필터·정렬·페이지)은 **전부 주소창에 담는다**. 필터를 건 화면을 그대로
공유·북마크할 수 있고, 상세를 보고 뒤로 와도 조건이 남는다.

## 2. 컴포넌트와 동작 규칙

### 2.1 서랍 vs 모달 — 이 시스템의 핵심 구분

| | 서랍 `AppDrawer` | 모달 `AppDialog` |
|---|---|---|
| 목적 | 맥락을 **지킨다** | 맥락을 **끊는다** |
| 쓰는 곳 | 상세 조회, 로그, 실시간 모니터링 | 정지·삭제·강제 종료 등 되돌릴 수 없는 동작 |
| 막(scrim) | 옅게 (0.28) — 뒤가 비쳐야 한다 | 진하게 (0.5) |
| 바깥 클릭 | 닫힘 | 닫힘 (처리 중에는 잠금) |
| 첫 포커스 | 닫기 버튼 | 확인 버튼, **위험하면 취소 버튼** |

서랍의 막이 옅은 것은 장식이 아니다. 뒤가 보여야 "아직 그 목록 위에 있다"가
전달된다. 반대로 모달의 막이 옅으면 경고가 가벼워 보인다.

**서랍은 가볍게 닫힌다 — 바깥을 누르기만 해도 닫힌다.** 그래서 서랍 안에서
파괴적 동작을 곧바로 실행하지 않는다. 서랍 위에 모달을 겹쳐 한 번 더 붙잡는다
(`UserPeekDrawer` 참고).

> 겹쳐 뜨는 것의 접근성 처리(포커스 가둠 · Esc · 스크롤 잠금 · 포커스 복귀)는
> [`useOverlay`](src/composables/useOverlay.ts) 한 곳에 있다. 특히 스크롤 잠금은
> **열린 개수를 센다** — 서랍 위 모달이 닫힐 때 잠금이 풀려 뒤 화면이 스크롤되는
> 버그를 막기 위해서다. 검사로 못박아 뒀다.

### 2.2 상태 배지 `StatusBadge`

```vue
<StatusBadge tone="ok">활성</StatusBadge>
<StatusBadge tone="danger" pulse>처리 중</StatusBadge>
<StatusBadge tone="accent" dotless>관리자</StatusBadge>
```

- **색만으로 말하지 않는다.** 이 콘솔의 `--ok` 초록과 `--danger` 빨강은
  2형 색각에서 사실상 같은 색이다. 그래서 배지는 **항상 글자를 함께 둔다** —
  색은 훑을 때 짚어 주는 보조 신호일 뿐 정보를 지고 있지 않다.
- **`pulse` 는 '지금 이 순간에도 값이 바뀌는 중'일 때만.** 그냥 '정상'에 맥동을
  달면 화면 곳곳이 깜빡여, 정작 움직여야 할 것이 묻힌다. **움직임도 잉크다.**
- **`dotless` 는 상태가 아닌 것에.** 점은 '상태'를 뜻하므로 '관리자' 같은
  분류에 붙이면 잘못된 신호가 된다.

상태 → 색의 대응은 **한 곳에서만 정한다**. `statusTone()` 이 돌려주는 값은
색 이름(`green`)이 아니라 토큰 이름(`ok`)이다 — 호출부가
`` `badge-${statusTone(...)}` `` 로 클래스를 만들기 때문에, 색 이름을 돌려주면
`base.css` 에 없는 클래스가 만들어져 배지가 통째로 색을 잃는다.

### 2.3 표와 빠른 동작

- 머리글은 `sticky`. 스크롤해도 어느 열인지 알아야 한다.
- 숫자는 등폭(`tabular-nums`) · 우측 정렬. 값이 갱신될 때 자릿수가 흔들리면
  읽는 사람이 계속 초점을 다시 맞춰야 한다.
- 해시·경로·ID 는 등폭 글꼴 + `.truncate`.
- **줄 hover 에서만 빠른 동작이 나타난다.** 서른 줄에 버튼이 늘 떠 있으면
  표가 버튼 밭이 되어 정작 데이터가 안 읽힌다.
  단, 감춤은 `opacity` 로만 한다 — `display:none` 은 Tab 순서에서도 지워
  마우스 없이는 닿을 수 없게 만든다. 터치 기기(`hover: none`)에서는 늘 보인다.
- **줄 전체가 눌려 서랍이 열린다.** 이름의 링크는 클릭을 삼켜(`@click.stop`)
  전체 상세로 간다 — 새 탭으로 열거나 주소를 복사하는 길이 막히면 안 된다.
  키보드에서는 `tabindex="0"` + Enter/Space 로 같은 일을 한다.

> 같은 요소에 `@keydown.enter` 와 `@keydown.space` 를 따로 달지 말 것.
> 한쪽이 조용히 사라진다. 키 판별은 핸들러 안에서 직접 한다.

### 2.4 자주 쓰는 조건(preset)

필터 상자를 각각 맞추는 일은 별것 아닌 것 같지만 하루에 스무 번이면 스무 번의
잔손질이다. 게다가 **관리자가 실제로 찾는 것은 정해져 있다** — 대개 '지금 문제가
있는 것'이다. 그 질문 하나를 버튼 하나로 만든다.

- 표 **위**에 둔다. 필터를 손으로 맞추기 전에 눈에 들어와야 쓴다.
- 지금 조건이 어느 묶음과 정확히 같을 때만 켜진 것으로 표시한다.
- 알약 모양(`999px`)을 쓰지 않는다. 다른 컨트롤이 전부 작은 라운딩이라
  칩만 둥글면 다른 앱에서 온 것처럼 보인다.

### 2.5 지표 타일과 스파크라인

`StatTile` 은 라벨 → 값 → 보조설명 순서로 쌓고 **값만 크게** 키운다.

추세선은 **줄 수 있는 지표에만** 단다. `'오류율 2.1%'` 는 그 자체로 좋고 나쁨을
말하지 않는다 — 30분째 2.1% 인 것과 방금 0.2% 에서 치솟은 2.1% 는 완전히 다른
상황이다. 하지만 시계열이 없는 지표('가동', '지금 활동 중')에 자리를 채우려고
아무 계열이나 그려 넣으면, 그 선이 무엇을 뜻하는지 아무도 설명할 수 없는
장식이 된다.

스파크라인의 축은 0 이 아니라 최솟값에서 시작한다(크기는 옆의 숫자가 이미
말한다). 다만 **변동 폭이 값에 비해 무시할 만하면 평평하게 그린다** — 그러지
않으면 1000 → 1001 이 0 → 1000 과 똑같이 극적으로 보인다. 눈금 없는 그림에서
그건 거짓말에 가깝다.

### 2.6 로딩과 빈 상태

`AsyncSection` 이 로딩·오류·빈 상태를 한 규칙으로 처리한다. 핵심 규칙:
**이미 데이터가 있으면 갱신 중이어도 계속 보여준다.** 2초마다 갱신되는 화면에서
새로고침마다 스피너로 비우면 내용이 깜빡여 읽을 수가 없다. 갱신 표시는 헤더의
작은 스피너로 충분하다.

빈 상태 문구는 **상황을 구분해서** 쓴다 — "조건에 맞는 사용자가 없습니다"와
"아직 가입한 사용자가 없습니다"는 관리자가 할 일이 다르다.

## 3. 디자인 토큰

### 3.1 규칙

1. **색은 '의미'에만 쓴다.** 상태와 링크·선택에만 색이 붙고 나머지는 회색이다.
   의미 없는 색이 늘면 정작 중요한 빨강이 눈에 안 들어온다.
2. **경계는 최소한으로.** 구획은 여백과 타이포 위계가 먼저 하고, 선은 정말
   필요할 때만 1px. 그림자는 '떠 있는 것'에만.
3. **숫자는 표처럼.** 등폭 숫자로 자릿수를 맞추고 우측 정렬.
4. **여백은 4px 배수.** 기본 행 높이를 낮게 잡는다(`--row-h: 34px`).
5. **하드코딩된 색값을 `base.css` 밖에 두지 않는다.** 라이트/다크 모두 1급이다.

### 3.2 역할 토큰

| 토큰 | 쓰임 | 라이트 | 다크 |
|---|---|---|---|
| `--bg` | 화면 바닥 | `#f7f8fa` | `#0f1216` |
| `--surface` | 판·표·상단 바 | `#ffffff` | `#171c22` |
| `--surface-2` | 표 머리·발, 입력 배경 | `#f7f8fa` | `#1a1f26` |
| `--surface-3` | 눌린 상태, 중립 배지 | `#eff1f4` | `#212832` |
| `--line` / `--line-strong` | 구분선 / 컨트롤 테두리 | `#e6e9ee` / `#dce0e6` | `#2a323e` / `#333c4a` |
| `--ink` … `--ink-4` | 본문 → 가장 옅은 보조 글자 | `#171b21` … `#98a1b0` | `#f0f3f6` … `#6b7684` |
| `--accent` | 링크·선택·현재 위치 | `#3056d3` | `#7d9bff` |
| `--ok` / `--warn` / `--danger` / `--info` | 상태 | 진한 값 + `-bg` 옅은 값 쌍 | 저채도 어두운 `-bg` |

의미색은 **'진한 값(글자) + 옅은 값(배경)' 한 쌍으로만** 존재한다. 쌍을 넘어
색조를 늘리기 시작하면 규칙이 무너진다.

다크에서 배경을 순검정으로 두지 않는다 — 순검정 위의 흰 글씨는 대비가 지나쳐
잔상이 남는다. 또 '옅은 배경'을 색상 자체의 저채도 어두운 값으로 바꿔야 배지가
형광펜처럼 튀지 않는다.

### 3.3 차트 토큰은 UI 토큰과 다르다

**차트의 색으로 UI 의 색을 그대로 쓰면 안 된다.** 화면의 글자·테두리는 읽히기만
하면 되지만, 차트의 면(面)은 넓게 칠해지므로 배경 대비와 색각 이상에서의 구분이
**별도로** 성립해야 한다.

이 콘솔의 차트가 초록을 쓰지 않는 이유가 그것이다. `--ok` 초록과 `--danger`
빨강은 2형 색각에서 ΔE 4.3(라이트) · 3.2(다크) 로 사실상 같은 색이다. 배지에서는
글자가 함께 있어 괜찮지만, **색만 남는 차트 면에는 쓸 수 없다.** 그래서 양극을
파랑↔빨강으로 두고, 좋고 나쁨은 기준선의 어느 쪽인지가 말하게 한다.

순서가 있는 단계(미시작 → 학습 중 → 완료)는 **한 색상의 밝기 단계**로 그린다.
서로 다른 색을 쓰면 별개의 것으로 읽히지만 실제로는 같은 축 위의 앞뒤다.

### 3.4 타이포그래피

| 자리 | 크기 / 굵기 |
|---|---|
| 화면 제목 `page-title` | 17px / 600 |
| 판 제목 `panel-title` | 13px / 600 |
| 구획 제목 `section-title` | 12px / 600 · 대문자 · `--ink-3` |
| 본문 | 13px / 400 |
| 표 본문 | 12.5px |
| 표 머리 · 보조 | 11.5px / `--ink-3` |
| 지표 값 `tile-value` | 21px / 600 |

글꼴은 Sans(Pretendard / system-ui)와 Mono(`ui-monospace` 계열) 두 벌. 숫자·ID·
경로·해시는 전부 Mono + `tabular-nums`. 한국어는 어절 중간에서 끊기면 읽는 속도가
크게 떨어지므로 `word-break: keep-all`.

라운딩은 작게(4 / 6 / 8px). 큰 라운딩은 소비자용 앱의 어휘고, 밀도 높은 도구에서는
요소가 실제보다 커 보여 화면을 낭비한다.

## 4. Tailwind 로 옮길 때

이 콘솔은 Tailwind 를 쓰지 않는다. **CSS 변수 토큰 + 의미 클래스** 방식이고,
그편이 이 도구에는 낫다고 판단했다.

- 테마 전환이 `data-theme` 속성 하나로 끝난다. Tailwind 의 `dark:` 변형으로
  같은 일을 하려면 색이 붙는 모든 자리에 변형을 하나씩 더 써야 한다.
- 위의 색각 검증(ΔE)을 거친 차트 토큰은 Tailwind 기본 팔레트에 대응물이 없다.
  `emerald-500`/`rose-500` 을 그대로 쓰면 2형 색각에서 구분되지 않는다.

다만 규칙 자체는 프레임워크와 무관하다. 옮겨야 한다면 `tailwind.config` 에
토큰을 그대로 심는 것으로 시작한다.

```js
// tailwind.config.js — 값을 복제하지 말고 변수를 가리키게 한다.
// 그래야 테마 전환이 계속 data-theme 하나로 끝난다.
export default {
  darkMode: ['selector', ':root[data-theme="dark"]'],
  theme: {
    extend: {
      colors: {
        bg: 'var(--bg)',
        surface: { DEFAULT: 'var(--surface)', 2: 'var(--surface-2)', 3: 'var(--surface-3)' },
        line: { DEFAULT: 'var(--line)', strong: 'var(--line-strong)' },
        ink: { DEFAULT: 'var(--ink)', 2: 'var(--ink-2)', 3: 'var(--ink-3)', 4: 'var(--ink-4)' },
        accent: { DEFAULT: 'var(--accent)', ink: 'var(--accent-ink)', bg: 'var(--accent-bg)' },
        ok: { DEFAULT: 'var(--ok)', bg: 'var(--ok-bg)' },
        warn: { DEFAULT: 'var(--warn)', bg: 'var(--warn-bg)' },
        danger: { DEFAULT: 'var(--danger)', bg: 'var(--danger-bg)' },
        info: { DEFAULT: 'var(--info)', bg: 'var(--info-bg)' },
      },
      borderRadius: { 1: '4px', 2: '6px', 3: '8px' },
      fontFamily: { sans: 'var(--sans)', mono: 'var(--mono)' },
    },
  },
};
```

대응 예시:

| 이 콘솔 | Tailwind |
|---|---|
| `.panel` | `bg-surface border border-line rounded-3` |
| `.badge.badge-ok` | `inline-flex items-center gap-1.5 h-[19px] px-[7px] rounded-1 text-[11px] font-semibold bg-ok-bg text-ok` |
| `.btn` | `inline-flex items-center justify-center gap-1.5 h-[30px] px-[11px] rounded-2 border border-line-strong bg-surface text-[12.5px]` |
| `.drawer` | `w-full max-w-[460px] h-full bg-surface border-l border-line-strong flex flex-col` |
| `.num` | `font-mono tabular-nums text-[12px]` |

**Slate 램프를 그대로 쓰지 말 것.** 이 콘솔의 중립 램프는 약간 푸른 기를 섞어
화면이 탁해 보이지 않게 조정한 값이고, 다크 램프는 라이트를 뒤집은 것이 아니라
따로 고른 단계다.

## 5. 새 화면을 만들 때 확인할 것

- [ ] 색을 새로 썼는가? → 상태나 선택을 뜻하는가. 아니면 회색으로 돌린다.
- [ ] 하드코딩한 색값이 `base.css` 밖에 있는가? → 토큰으로 뺀다.
- [ ] 상태를 색으로만 표시했는가? → 글자나 아이콘을 함께 둔다.
- [ ] 되돌릴 수 없는 동작에 확인 단계가 있는가? → `AppDialog`.
- [ ] 확인 문구가 **무슨 일이 벌어지는지** 말하는가? → "정말 하시겠습니까?" 는
      아무 정보가 없다.
- [ ] 상세를 보느라 목록을 잃는가? → `AppDrawer` 를 검토한다.
- [ ] 목록의 조건이 주소창에 남는가? → `useQuerySync`.
- [ ] 로딩 중에 기존 데이터가 사라지는가? → `AsyncSection` 규칙을 따른다.
- [ ] 빈 상태 문구가 상황을 구분하는가?
- [ ] 키보드만으로 끝까지 쓸 수 있는가? Tab 이 새어 나가지 않는가?
- [ ] 다크 테마에서 확인했는가?
